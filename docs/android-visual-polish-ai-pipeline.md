# 安卓版显示效果优化方案：生图 AI 协作管线

> 目标：优化 Android 原生版的 UI 与地图描画效果，并保证「软件效果 == 效果图」。
> 硬约束：协作的编程模型**不支持识图**（无法看效果图/截图），因此一致性的保障
> 必须建立在**数值化、机器可读的设计产物**上，而不是「照着图改代码」。
>
> 最后更新：2026-08-13

---

## 0. 总思路：三条腿撑起「效果图 == 软件」

| 机制 | 说明 |
|---|---|
| ① **双产出** | 让生图 AI 每次输出两类产物：**效果图**（PNG，给人看，定审美方向）+ **机器可读产物**（HTML 原型 / design-tokens.json，给机器看，定精确数值）。图片负责"好不好看"，JSON/HTML 负责"值是多少"。 |
| ② **token 单源** | 代码侧把 `MapVisualTokens.kt`（已存在）扩展为**唯一视觉真相源**：颜色、字号、间距、圆角、描边、水彩羽化半径、暗角强度、河流线宽…… GLES2（`MapRenderer` / `WatercolorBuilder` / `TerrainTextureBuilder`）与 Compose（各 Sheet / 时间轴 / 泡泡）全部从这里取值，禁止散落硬编码。效果图定稿 → 改一个 token 文件 → 全端一致。 |
| ③ **双通道校验** | **人通道**：真机/模拟器截图 vs 效果图，人眼比对审美是否一致。**机器通道**：`scripts/check-visual-tokens.mjs` 把 design-tokens.json 与 `MapVisualTokens.kt` 做数值 diff，保证"数值一致"100% 可验证——这是模型不能识图时的唯一可靠闭环。 |

一句话：**图片只定风格，JSON 定数值，代码吃 JSON，脚本验数值。**

---

## 1. 协作管线总览（5 步）

```
① 现状快照         ② 生图定风格          ③ 数值化定稿              ④ 落地               ⑤ 校验
截图 + 当前 token 表 → 逐屏效果图          → HTML 原型 + tokens.json  → 改 token + 模块      → token diff + 截图对比
（附录 A 已备好）     （话术 2.4）          （话术 2.5 / 2.6）          （第 3/4 节清单）      （5.2 / 5.3 SOP）
```

每步的产出物：

1. **现状快照**：真机截图若干 + 附录 A 的「当前色值表」——直接粘给 AI，让它知道起点在哪。
2. **生图定风格**：用话术 2.4 逐屏生成效果图（建议每屏生成 2~3 版备选），人选定风格方向。
3. **数值化定稿**：对选中的效果图，让 AI ① 输出单文件 HTML 原型（浏览器可交互预览，内联样式全部是字面量数值）② 输出 design-tokens.json。**这两份才是真正进代码的东西。**
4. **落地**：按第 3、4 节的清单，把 token 灌进 `MapVisualTokens.kt`，逐模块改代码。
5. **校验**：跑 token diff 脚本（机器验证数值一致）；构建 APK 截图给人比对（人验证审美一致）；P20 真机回归性能。

## 2. 生图 AI 话术库（直接复制粘贴）

> 使用说明：以下话术面向 **ChatGPT（GPT-4o 图像生成）** 网页版。
> - 每次开启**新对话**，先发「2.1 系统设定」，同一对话内继续逐屏生成，保证风格延续。
> - 「2.3 可实现效果清单」建议**每次请求都附上**，防止 AI 画出 Android 做不出的效果。
> - 效果图里**中文文字必然乱码**：要求 AI 把文字模糊化/用色块占位，文字细节由 HTML 原型承载（见 2.9 防坑清单）。

### 2.1 系统设定 prompt（每轮对话第一条）

```
你是中国风历史地图 App 的 UI/视觉设计总监。在接下来的所有对话中，请先记住这份设计宪法：

1. 美学基调：宋代文人美学——宣纸、水墨、留白、朱砂印章、淡金点缀。
   参考：宋代山水画（马远、夏圭式大留白）、古籍刻本排版、汝窑低饱和质感。

2. 色彩纪律：所有颜色必须来自「宣纸米白 / 墨褐 / 朱砂红 / 赭金 / 黛青 / 茶绿」色系，
   整体饱和度 ≤ 35%。禁用：霓虹色、纯黑、纯白、现代渐变色（紫、蓝紫）、荧光描边。

3. 质感纪律：平面水彩晕染 + 纸面颗粒 + 单层淡墨描边。禁用：玻璃拟态(毛玻璃)、
   金属质感、3D 悬浮阴影、描边发光、拟物按钮。

4. 文字纪律：中文一律衬线（宋/楷体），标题可竖排，年份数字用衬线西文；
   文字间距宽松（字距 2~8）、有"古籍刻本"的疏朗感，不做现代扁平无衬线大字。

5. 层级纪律：地图内容（疆域色块、河流、山脉、地名）永远是最底层的"纸面内容"，
   控件（时间轴、泡泡、按钮）是浮在纸面上的"笺条/印章"，半透明、有细墨描边，
   不遮挡地图叙事主体。

6. 实现纪律：所有效果必须能用 Android Canvas + OpenGL ES 2.0 实现
   （可：羽化、径向渐变、颗粒噪点、虚线、圆角、描边、单层阴影、alpha 混合；
   不可：多层复杂阴影、逐像素滤镜、复杂 SVG 滤镜）。见随后的"可实现效果清单"。

7. 输出纪律：每张效果图之后，用 JSON 列出该画面用到的全部色值（hex），
   并标注每个关键元素的尺寸比例（相对屏宽的百分比）。
```

```

2. 地图疆域水彩色块边缘、河流山脉的墨色层次不够精致。
3. 时间轴、泡泡、图例等控件的"笺条/印章"质感还不够统一精致。
4. 字体受设备默认衬线影响，效果不稳定。
```

### 2.3 可实现效果清单（每次请求附上，防止画飞）

```
【可实现的视觉手段（请只用这些）】
- 纯色填充 + 任意透明度；两个纯色之间的线性/径向渐变（GLES2 仅全屏 2D 渐变，控件用 Compose Brush）。
- 羽化（模糊半径可调）：色块边缘晕开、渗墨效果。
- 颗粒噪点纹理叠加（screen/soft-light 近似混合）。
- 单层描边（实线/虚线/点线），任意粗细；圆角矩形；圆形。
- 单层阴影：向一个方向偏移 + 模糊的低透明墨色阴影（Compose shadow / Canvas setShadowLayer）。
- 中心提亮 + 四角暗角（smoothstep 径向衰减）。
- 全屏或控件级 alpha 淡入淡出、位移动画、缩放动画（时间可调）。

【不可实现/不要画的】
- 玻璃拟态（backdrop-filter 毛玻璃）、多层 3D 阴影、发光/辉光描边、金属/塑料质感。
- 需要逐像素滤镜或复杂 SVG 滤镜的效果。
- 大量 8px 以下的细节纹理（会被羽化和颗粒吃掉）。
```

### 2.5 HTML 原型 prompt（一致性核心，必须做）

> 这是「软件和效果图一致」的关键一步：HTML 里每个值都是字面量，直接可翻译成 Compose。

```
请把第 X 版定稿效果图实现为一个【单文件 HTML 原型】：
- 内联 CSS、无外部依赖（不引字体文件时用 font-family: 'Noto Serif SC', 'Songti SC', serif），
  可直接在浏览器打开。
- 页面为竖屏手机画布（宽 720px，高 1560px，按效果图排版），所有文字用真实中文文案。
- 硬性要求：
  1) 所有颜色写成 hex/rgba 字面量（不用 CSS 变量、不写名字如 "white"）；
  2) 所有圆角/描边/字距/行高/透明度/阴影偏移都写具体数值；
  3) 阴影只用"单层低透明墨色阴影 + 单层内描边"，禁用 box-shadow 多层、backdrop-filter、
     clip-path 描边、SVG 滤镜等 Android 无法 1:1 复刻的效果；
  4) 每个主要区块用 HTML 注释标明它对应 App 的哪一层
     （如 <!-- 顶栏 topbar --> <!-- 时间轴 timeline --> <!-- 泡泡 bubble -->）；
  5) 在 <style> 最前面用注释块输出"设计 token 表"：
     color / spacing / radius / stroke / type(字号/字重/字距/行高) 每项 = 具体值。
- 页面结构按地图(背景层) → 水彩疆域(可用 CSS radial-gradient + 模糊示意) →
  标注 → 泡泡 → 顶栏 → 时间轴 → 抽屉 的顺序叠放。
之后我会把这份 HTML 1:1 翻译成 Jetpack Compose 代码，所以数值的确定性比美观更重要。
```

## 3. 地图描画优化清单（GLES2 / Canvas 渲染层）

> 文件：`MapRenderer.kt`、`WatercolorTexture.kt`、`TerrainTexture.kt`、`MapVisualTokens.kt`

### 3.1 第一批（视觉收益最大、风险低）

| # | 项 | 现状 | 改法 | 对齐效果图 |
|---|---|---|---|---|
| 1 | **抗锯齿 MSAA** | `setEGLConfigChooser(8,8,8,8,16,8)` 无多重采样，疆域边缘有锯齿 | 自定义 EGLConfigChooser 优先要 4x MSAA，失败降级无采样；`GLES20.glEnable(GL_MULTISAMPLE)`（真机上 MSAA 由 EGL 配置决定） | 边缘如效果图的渗墨毛边而不是像素锯齿 |
| 2 | **纹理 mipmap + 各向异性过滤** | 水彩/山水纹理只有 `GL_LINEAR`，缩小到全图视野时斑驳点闪烁（混叠），放大 24x 时整图糊 | 上传纹理时 `GLES20.glGenerateMipmap` + `GL_LINEAR_MIPMAP_LINEAR`；探测 `GL_EXT_texture_filter_anisotropic` 支持则开 4x/8x | 缩小不闪、放大相对锐利 |
| 3 | **河流曲线平滑** | `TerrainTexture.kt` 直接 `lineTo` 折线（数据点多还好，稀疏处可见折角） | Catmull-Rom → 贝塞尔插值后再光栅化 | 效果图的柔和曲线水痕 |
| 4 | **时期/朝代切换交叉淡入** | `setOverlay()` 直接换纹理，切换瞬间闪变 | `FRAG_TEX` 加 `uAlpha` uniform，切换时 300~500ms tween 淡入（旧纹理保留至新纹理淡入完成） | 转场如墨色晕开 |
| 5 | **shader 参数 token 化** | 暗角 0.38、中心提亮 0.10、颗粒 0.10 等硬编码在 `FRAG_BG` 字符串常量里 | 抽成 uniform（`uVignette/uCenterLight/uGrain`），每帧从 `MapTokens.map.*` 读 | 效果图定稿的暗角强度可一行改掉 |
| 6 | **水彩管线参数 token 化** | `WatercolorBuilder` 各层 alpha/羽化半径/斑驳数量/描边宽全部魔法数 | 全部改为读 `MapTokens.map.watercolor.*`（附录 A 已整理现值） | 效果图的"水彩浓度"逐项可调 |
| 7 | **山水管线参数 token 化** | `TerrainTextureBuilder` 河流三层线宽/alpha、山形 alpha 魔法数 | 同上，读 `MapTokens.map.terrain.*` | 同上 |
| 8 | **标签卡片可读性** | 标签纸底 `0xD9F7F2E6` 无阴影，在浅色疆域上对比弱 | 卡片加单层淡墨阴影（`setShadowLayer`）+ 描边颜色入 token；政权名与城市名分两级字号对比 | 效果图"地名浮于纸面"的层次 |
| 9 | **年份水印 token 化** | `120.sp / 0x173A3428 / 8.sp` 写死在 MapScreen | 入 `MapTokens.type.yearWatermark`，可加竖排（`Modifier` 或 Canvas 竖排绘制）选项 | 效果图的大留白水印 |

### 3.2 第二批（进阶质感，按效果图定稿再决定做哪些）

| # | 项 | 说明 |
|---|---|---|
| 10 | 水彩 LOD（缩放分级重生成） | 目前纹理上限 2048（P20 内存安全），放大 8x 以上明显糊。方案：缩放停止（debounce 300ms）且 zoom > 4 时，按当前视野重新生成局部高清水彩纹理。内存/耗时敏感，列为可选项 |

| 12 | 山形笔触重绘 | 按 2.7-2 生成的矢量山形素材替换 `drawMountainGlyph` 的三角峰；或增加皴法短线层（按种子撒短斜线） |

### 5.2 机器校验脚本 `scripts/check-visual-tokens.mjs`（新增）

> 模型不能识图，所以"数值一致"用脚本证明：

