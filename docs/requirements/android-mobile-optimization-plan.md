# Android 手机端体验优化计划

> **⚠️ 历史文档（WebView 架构时代）**：本计划基于早期「Android WebView 壳 + three.js + JS bridge」实现，部分问题与方案仅适用于该架构。
> Android 端已于 2026-08 重构为 Kotlin 原生实现（Compose + GLES2，弃用 WebView），当前架构与最终落地见
> `AGENTS.md`「Android 原生版」章节、`docs/requirements/refactor-requirements.md` 与 `docs/architecture/android-native-rewrite-plan.md`。
> 本文件仅作历史参考，其中的 Room/Android Bridge/WebView 描述已不反映现状。

> 适用设备：当时基于华为 P20（EML_AL00，Android 10）WebView 验证
>
> 目标：优化移动端布局、可读性、触摸交互和播放流程。
>
> 状态：`[ ]` 未开始　`[~]` 进行中　`[x]` 已完成　`[-]` 暂缓　（**历史文档，不再更新**）
>
> 最后更新：2026-08-10（已冻结）

## 一、当前观察结论

当前手机端已经可以正常运行：

- three.js 地图和历史疆域正常渲染
- 朝代切换正常
- 时间轴、事件泡泡、事件流、详情面板、设置面板正常工作
- Room 数据和 Android bridge 契约正常
- WebView Chrome 83 兼容性问题已处理

从真机截图和交互检查看，主要问题集中在移动端信息密度和控件布局：

1. 地图标签、事件泡泡、辅助地点之间存在重叠。
2. 底部时间轴在竖屏下过于拥挤，触摸区域偏小。
3. 事件流打开后几乎覆盖整个地图，缺少当前年份上下文。
4. 详情面板顶部年份、分类、时期、分享和关闭按钮较拥挤。
5. 政权图例在小屏幕上占用较多空间。
6. 播放到终点后缺少明确的“播放完成/重新播放”反馈。
7. 地图标签和背景对比度偏低，当前事件不够突出。
8. Android 返回键尚未按详情、设置、事件流的层级优先关闭。

## 二、设计原则

- **移动端优先**：优先保证竖屏单手操作，再兼容横屏。
- **主叙事优先**：当前事件 > 主要政权 > 核心城市 > 辅助地理信息。
- **桌面端不回归**：移动端优化主要放在媒体查询和移动端显示策略中，不改变桌面端既有布局。
- **数据契约不变**：不修改 Room schema、Android bridge 方法签名和 GeoJSON 响应结构。
- **旧 WebView 可用**：继续兼容 Chrome 83，避免使用 Chrome 86+ 才支持的 DOM API。
- **触摸目标足够大**：可操作控件实际触摸区域不小于 44px。

## 四、第一阶段：移动端地图信息分层

### 目标

降低地图文字密度，确保当前事件和主要政权清晰可见。

### 任务

- [ ] 增加统一的移动端紧凑显示策略。
- [ ] 手机端默认减少辅助政权标签数量。
- [ ] 限制同时显示的城市和地点标签数量。
- [ ] 河流、山脉、地点标签在移动端默认降低透明度或按设置隐藏。
- [ ] 当前事件泡泡保持最高显示层级。
- [ ] 事件泡泡与政权标签、城市标签统一参与碰撞避让。
- [ ] 普通事件冲突时合并为 `+N` 聚合泡泡。
- [ ] 超出屏幕边缘的泡泡自动回收至可视区域。
- [ ] 保留事件真实位置与泡泡之间的指向线。

建议的移动端策略对象：

```js
{
  compact: true,
  maxPlaceLabels: 5,
  showSecondaryLabels: false,
  showAuxiliaryLabels: false
}
```

### 验收标准

- 当前事件泡泡不被普通地名遮挡。
- 地图中下部不出现大面积文字堆叠。
- 事件、政权、城市具有明显视觉层级。
- 桌面端标签数量和布局不发生回归。

## 五、第二阶段：重做移动端时间轴

### 目标

让时间轴适合单手操作，避免播放按钮、年份、范围、刻度全部挤在一行。

### 任务

- [ ] 移动端时间轴改为两行布局。
- [ ] 第一行显示播放按钮、当前年份和年份范围。
- [ ] 第二行显示轨道、滑块和事件刻度点。
- [ ] 轨道实际触摸区域扩大到至少 44px。
- [ ] 滑块触摸区域扩大到至少 44px × 44px。
- [ ] 移动端减少刻度文字，仅显示起始年、结束年及少量中间刻度。
- [ ] 密集事件点只保留可点击点，避免标签文字全部展开。
- [ ] 增加 `env(safe-area-inset-bottom)`，避开系统导航区域。
- [ ] 增加横屏时间轴布局规则。

建议布局：

```text
[播放] 1279 年                         960 — 1279

|------●---------●---------●---------●------|
```

### 验收标准

- 单手可以稳定拖动年份。
- 播放按钮与系统导航区不冲突。
- 事件刻度点不会互相遮挡。
- 竖屏、横屏均能正常操作。
- 时间轴不会遮挡当前事件的核心区域。

## 六、第三阶段：事件流抽屉优化

### 目标

让事件流成为有上下文的历史浏览器，而不是简单的全屏列表。

### 任务

- [ ] 顶部增加当前朝代和当前年份摘要。
- [ ] 显示已出现事件数/总事件数，例如“已出现 23 / 30 个事件”。
- [ ] 将列表项分为已出现、当前事件、未出现三种状态。
- [ ] 当前年份事件使用高亮样式。
- [ ] 时间轴推进到新事件时，事件流自动定位到该事件。
- [ ] 用户手动滚动后暂缓自动定位。
- [ ] 增加“回到当前”操作。
- [ ] 搜索时显示匹配数量。
- [ ] 移动端抽屉底部增加安全区 padding。
- [ ] 支持向下滑动关闭抽屉（若不影响现有滚动）。

### 验收标准

- 用户能快速知道当前播放到哪个年份。
- 用户能区分已经播放和未播放事件。
- 当前事件可以一键定位。
- 搜索结果数量明确。
- 抽屉打开后仍保留少量地图上下文。

## 七、第四阶段：详情面板优化

### 目标

降低顶部控件拥挤程度，提升阅读和关闭的可靠性。

### 任务

- [ ] 增加顶部拖拽指示条。
- [ ] 将关闭按钮固定在独立的右上角区域。
- [ ] 将分享按钮移到标题下方或详情内容底部。
- [ ] 元信息标签允许换行。
- [ ] 标题移动端最多显示两行。
- [ ] 详情正文优化中文行高和段间距。
- [ ] 面板底部增加安全区 padding。
- [ ] 相关事件改为更紧凑的卡片布局。
- [ ] 打开详情时自动滚动到顶部。
- [ ] 打开详情时自动暂停时间轴。
- [ ] 关闭详情后保持暂停，避免用户误以为仍在播放。

建议移动端顶部结构：

```text
          ─────
1271 年
军事·领土
崖山 · 元朝建立                         [关闭]
```

### 验收标准

- 分享和关闭按钮不容易误触。
- 长标题不溢出。
- 详情可以完整滚动到底部。
- 最后一个相关事件不被系统导航栏遮挡。
- 详情打开后年份不会继续自动跳变。

## 八、第五阶段：政权图例和顶栏优化

### 目标

减少非核心控件对移动端地图空间的占用。

### 任务

- [ ] 移动端图例默认折叠。
- [ ] 默认只显示当前主政权和少量重要政权。
- [ ] 增加“展开图例”操作。
- [ ] 图例展开后支持横向滚动。
- [ ] 顶栏按钮统一最小 44px 触摸尺寸。
- [ ] 减少移动端顶栏横向间距。
- [ ] 处理状态栏、刘海和安全区。
- [ ] 未读数字只在确实有新事件时显示。
- [ ] 朝代切换时清除旧朝代未读数。
- [ ] 检查 `showOverlay=false` 时政权标签和图例是否同步隐藏。

### 验收标准

- 图例不再压缩时间轴。
- 顶栏按钮在 P20 上可以准确点击。
- 设置开关与实际显示结果一致。
- 朝代切换后没有旧事件和旧政权标签残留。

## 九、第六阶段：播放流程和 Android 返回键

### 目标

让时间轴和系统返回行为符合移动端产品习惯。

### 任务

- [ ] 到达 `endYear` 时显示“本朝历史播放完毕”。
- [ ] 播放按钮变为“重新播放”。
- [ ] 点击重新播放后回到 `startYear`。
- [ ] 朝代切换后自动从新朝代起始年份开始。
- [ ] 点击事件泡泡时自动暂停播放。
- [ ] 关闭详情后保持暂停。
- [ ] Android 返回键优先关闭详情面板。
- [ ] 再次返回关闭设置面板。
- [ ] 再次返回关闭事件流。
- [ ] 所有面板关闭后才返回 WebView 历史或退出 App。

返回键优先级：

```text
详情面板 → 设置面板 → 事件流 → WebView 历史 → 退出 App
```

### 验收标准

- 播放结束状态明确。
- 用户知道如何重新播放。
- 点击事件后不会继续跳年。
- Android 返回键不会直接退出应用。

## 十、第七阶段：性能和兼容性回归

### 目标

确保优化后仍适合 P20 的 Chrome 83 WebView 和 WebGL 性能。

### 任务

- [ ] 记录首屏加载时间。
- [ ] 记录地图初始化耗时。
- [ ] 记录朝代切换和时期切换耗时。
- [ ] 观察自动播放期间的帧率和卡顿。
- [ ] 限制低端设备上的 CSS2D 标签总数。
- [ ] 仅对可见事件执行碰撞计算。
- [ ] 降低低端设备每帧重排频率。
- [ ] 避免每帧创建和销毁 DOM。
- [ ] 验证横竖屏切换。
- [ ] 验证进入后台再恢复。
- [ ] 验证屏幕旋转。
- [ ] 验证 localStorage 持久化。
- [ ] 继续扫描 Chrome 83 不支持的浏览器 API。

### 建议指标

| 指标 | 目标 |
|---|---|
| 首屏可交互时间 | ≤ 3 秒 |
| 朝代切换完成时间 | ≤ 1.5 秒 |
| 时期切换完成时间 | ≤ 1 秒 |
| 自动播放地图交互 | 无明显卡顿 |
| 触摸控件最小尺寸 | ≥ 44px |
| 详情底部内容 | 可滚动到最后一项 |

## 十二、最终验收标准

完成后，P20 竖屏主界面应满足：

- [ ] 地图中没有大面积事件泡泡互相遮挡。
- [ ] 当前事件始终最醒目。
- [ ] 时间轴可单手拖动。
- [ ] 图例不会压缩时间轴。
- [ ] 事件流能显示当前播放进度。
- [ ] 详情面板能完整阅读并顺畅关闭。
- [ ] Android 返回键按面板优先级工作。
- [ ] 播放结束后用户知道如何重新播放。
- [ ] 设置开关与实际显示状态一致。
- [ ] Web 端和 Android 端 API 契约及核心功能保持一致。
- [ ] `npm run lint`、`npm run test`、`npm run build` 全部通过。
- [ ] `android/gradlew assembleDebug` 构建成功。
- [ ] APK 在 P20 真机安装并完成截图、交互回归。
